# Получение Root-доступа по сети (quasar-unlock)

Подробное практическое руководство по сетевой разблокировке умных колонок Яндекс (семейство Станций), получению постоянного доступа по ADB с правами `root` (`uid=0`) и защите от автоматических обновлений.

Метод основан на перехвате проверки обновлений через публичный сервер `quasar-unlock` и не требует разборки корпуса, пайки или программатора.

---

## 🧠 Как работает уязвимость

1. **Заводской сброс:** При сбросе Станции кнопками прошивка откатывается на базовый заводской образ (или сбрасывает изменяемый раздел `/data`).
2. **Отсутствие пиннинга SSL:** Системные демоны `syncd` и `updatesd` на заводской версии доверяют публичным доверенным цепочкам сертификатов.
3. **Подмена DNS:** Запрос колонки к `quasar.yandex.net` перенаправляется на сервер разблокировки (`179.254.167.126`).
4. **Инъекция параметров ADB:** Сервер подменяет ответ `/get_sync_info`, прописывая параметры:
   ```json
   "system_config": {
     "adbd": {
       "forceDisable": false,
       "remoteActivation": true,
       "network": true
     }
   }
   ```
5. **Активация сетевого отладчика:** Скрипт `activate_adb.sh` в прошивке колонки видит эти директивы, сохраняет маркеры автозагрузки в `/data/quasar/` и запускает `adbd` на сетевом порту **5555**.

## 🛠️ Что понадобится перед стартом (Чек-лист)

- [ ] **Роутер с возможностью настройки DNS** (Keenetic, OpenWrt, MikroTik, Asus) или второй смартфон в режиме точки доступа Wi-Fi;
- [ ] **Компьютер в той же локальной сети** с установленной утилитой `adb` ([инструкция по установке ADB](toolchain.md#adb-install));
- [ ] **Смартфон** с установленным приложением «Дом с Алисой» или «Яндекс»;
- [ ] Сама колонка и штатный блок питания.

## 🚀 Пошаговая инструкция разблокировки
<a id="dns-unlock"></a>

```text
[ Шаг 1: Аппаратный сброс ] ──► [ Шаг 2: Поиск в приложении ] ──► [ Шаг 3: Ввод Wi-Fi + ВКЛЮЧЕНИЕ DNS ]
                                                                                │
[ Шаг 6: Фиксация Root ]   ◄── [ Шаг 5: Проверка ADB ]       ◄── [ Шаг 4: Приём OTA и перезагрузка ]
```

### Шаг 1. Аппаратный сброс колонки до завода
Сброс полностью очищает пользовательский раздел `/data` и переводит прошивку в исходное состояние.

* **Станция Лайт / Мини 2 / Мини 3 / Стрит:**
  1. Отключите кабель питания (Type-C).
  2. Зажмите кнопку **отключения микрофона** (или кнопку паузы).
  3. Не отпуская кнопку, вставьте кабель питания обратно.
  4. Удерживайте кнопку **10–15 секунд**, пока подсветка не начнет мигать и Алиса не скажет: *«Начался сброс к заводским настройкам...»*.
* **Станция Миди / Станция 2:**
  1. Выдерните штекер питания.
  2. Зажмите центральную сенсорную кнопку (или кнопку микрофона сзади) и подключите питание.
  3. Дождитесь звукового сигнала и голосового сообщения о начале сброса.

После сброса дайте колонке 1–2 минуты загрузиться. Она начнет светиться фиолетовым/голубым цветом и поприветствует вас фразой: *«Привет! Чтобы меня настроить, откройте приложение...»*.

---

### Шаг 2. Начало привязки в приложении
1. Включите Bluetooth и геолокацию на смартфоне.
2. Откройте приложение **«Дом с Алисой»** (или «Яндекс»).
3. Нажмите **«+»** → **«Устройство с Алисой»**.
4. Смартфон обнаружит колонку и начнет первичную настройку.
5. Пройдите шаги до экрана: **«Выберите сеть Wi-Fi и введите пароль»**.

!!! danger "СТОП! На этом экране ничего не нажимайте!"
    Не нажимайте кнопку «Подключиться», пока не выполните Шаг 3 на роутере!

---

### Шаг 3. Включение подмены DNS на роутере (КРИТИЧЕСКИЙ ЭТАП)

Включить DNS нужно **строго на этом этапе**, когда колонка еще не подключилась к Wi-Fi.

Зайдите в панель управления вашего домашнего роутера и укажите DNS:
```text
179.254.167.126
```
Второй (резервный) DNS обязательно оставьте **пустым**!

=== "Keenetic (KeenOS)"
    * **В веб-интерфейсе:** «Сетевые правила» → «Домашняя сеть» → блок «Параметры IP и DHCP» → в поле **DNS 1** введите `179.254.167.126`, поле **DNS 2** сотрите → нажмите «Сохранить».
    * **Либо через CLI (быстро):**
      ```text
      ip host quasar.yandex.net 179.254.167.126
      system configuration save
      ```

=== "OpenWrt"
    Для заворачивания запросов без вмешательства в сеть других устройств:
    ```sh
    uci add firewall redirect
    uci set firewall.@redirect[-1].name='Quasar-Unlock'
    uci set firewall.@redirect[-1].src='lan'
    uci set firewall.@redirect[-1].proto='tcp udp'
    uci set firewall.@redirect[-1].src_dport='53'
    uci set firewall.@redirect[-1].dest_ip='179.254.167.126'
    uci set firewall.@redirect[-1].dest_port='53'
    uci set firewall.@redirect[-1].target='DNAT'
    uci commit firewall && /etc/init.d/firewall reload
    ```

=== "Раздача с Android-смартфона"
    Если роутер не позволяет менять DNS:
    1. Раздайте Wi-Fi с одного телефона (Точка доступа).
    2. Установите приложение **DNS Changer** на раздающий телефон и задайте `179.254.167.126`.
    3. Привязывайте колонку ко второму телефону.

!!! warning "Почему нельзя включать DNS заранее?"
    Во время Шага 2 приложение связывает колонку с вашим Яндекс ID через сервера паспорта. Если включить DNS раньше, колонка не сможет связаться с аккаунтом и выдаст ошибку сопряжения. DNS нужен именно в момент, когда колонка впервые лезет в Wi-Fi за прошивкой.

---

### Шаг 4. Подключение к Wi-Fi и получение прошивки

1. Теперь вернитесь в приложение на смартфоне и нажмите кнопку **«Подключиться»**.
2. Смартфон передаст колонке логин и пароль от Wi-Fi.
3. Колонка подключится к роутеру, получит адрес DNS `179.254.167.126` и запросит статус у `quasar.yandex.net`.
4. Сервер подмены перехватит запрос и скомандует активировать ADB.
5. Индикация колонки начнет мигать (скачивание и применение настроек), после чего колонка издаст системный звук готовности.

---

### Шаг 5. Подключение по ADB

1. Откройте панель роутера и найдите IP-адрес вашей колонки (например, `192.168.1.120`).
2. На компьютере в терминале выполните:
   ```sh
   adb connect 192.168.1.120:5555
   ```
3. Проверьте статус:
   ```sh
   adb devices
   ```
   Должна появиться строка:
   ```text
   192.168.1.120:5555    device
   ```
4. Вход в root-консоль:
   ```sh
   adb shell
   ```
   Приглашение командной строки покажет: `#` (`uid=0(root)`). Вы получили полный root-доступ!

---

### Шаг 6. Фиксация доступа и отключение OTA
<a id="kill-ota"></a><a id="ota"></a><a id="durable"></a>

Это действие нужно сделать **немедленно**, пока Яндекс не прислал официальное обновление поверх нашего доступа.

Скопируйте и вставьте в консоль колонки (`adb shell`) следующий блок команд:

```sh
# 1. Перемонтируем корневую систему в режим чтения-записи
mount -o remount,rw /

# 2. Создаем и навечно защищаем маркеры автозапуска ADB
mkdir -p /data/quasar
touch /data/quasar/activate_adb_quasmodrom
touch /data/quasar/activate_network_adb
chattr +i /data/quasar/activate_adb_quasmodrom /data/quasar/activate_network_adb 2>/dev/null

# 3. Вырезаем демона обновления updatesd из супервизора
if [ -f /etc/launch.json ]; then
    sed -i '/updatesd/d' /etc/launch.json
fi

# 4. Обезоруживаем скрипт установки обновлений
if [ -f /system/vendor/quasar/device_ota_update.sh ]; then
    echo '#!/bin/sh' > /system/vendor/quasar/device_ota_update.sh
    echo 'exit 0' >> /system/vendor/quasar/device_ota_update.sh
    chmod +x /system/vendor/quasar/device_ota_update.sh
fi

# 5. Портим публичный ключ проверки подписи OTA
if [ -f /etc/ota_script.pub ]; then
    echo "CORRUPTED_KEY" > /etc/ota_script.pub
fi

sync
echo "=== УСПЕХ: Root зафиксирован, OTA навсегда заблокирован! ==="
```

*(В репозитории также доступен готовый проверенный скрипт: [`contrib/yandex-noupdate.sh`](https://github.com/Marker284/yandex-station-extended/blob/main/contrib/yandex-noupdate.sh))*.

### Шаг 7. Возврат штатного DNS
Теперь можно зайти на роутер и **отключить DNS `179.254.167.126`**, вернув стандартные настройки провайдера. Ваша колонка навсегда останется с открытым ADB на порту 5555 и больше не сможет обновиться.

## 🔧 Траблшутинг (Решение частых проблем)

??? failure "1. Приложение выдает «Не удалось подключиться к Wi-Fi»"
    * **Причина:** Вы включили DNS `179.254.167.126` слишком рано (до этапа ввода пароля Wi-Fi).
    * **Решение:** Отключите DNS на роутере, сделайте сброс колонки заново, пройдите привязку до экрана ввода пароля Wi-Fi, и только затем включите DNS.

??? failure "2. Колонка подключилась к Wi-Fi, но порт :5555 закрыт (`Connection refused`)"
    * **Причина 1:** На роутере включена DNS-фильтрация (Яндекс.DNS, AdGuard, SafeDNS), которая заблокировала наш сервер. Отключите фильтрацию на роутере.
    * **Причина 2:** Колонка закэшировала старый IP Яндекса. Перезагрузите колонку по питанию (выдерните и вставьте провод через 5 секунд).
    * **Проверка с ПК:** выполните `dig +short quasar.yandex.net`. Должен возвращаться адрес `179.254.167.126`.

??? failure "3. adb connect пишет `unable to connect`"
    * Убедитесь, что компьютер и колонка находятся в **одной локальной сети** (не в гостевой сети Wi-Fi с изоляцией клиентов AP Isolation).
    * Проверьте пинг: `ping <IP_колонки>`.

## 🔌 Аппаратный доступ по UART (Serial)
<a id="serial"></a>

Если сетевой доступ недоступен, на системных платах Станций выведены аппаратные контакты UART (115200 бод, 3.3V). Подробнее об аварийном восстановлении и работе с загрузчиком U-Boot читайте в статье **[Раскирпичивание и восстановление](unbrick.md)**.
