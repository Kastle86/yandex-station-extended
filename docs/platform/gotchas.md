# Подводные камни и автономная работа

Сборник неочевидных ловушек, скрытых механизмов и граблей, с которыми сталкиваются разработчики при переводе Яндекс Станций на собственные серверы, изолировании от облака и глубокой модификации.

Материал составлен на основе реального опыта реверс-инжиниринга прошивок `quasar` 3.21.

---

## 🚫 1. Отсутствие Certificate Pinning (Работа без TLS)

Самое приятное и неожиданное открытие в коде `maind`: **в прошивке нет SSL-пиннинга сертификатов**.

* **HTTP-клиент** построен на стандартной `libcurl`, и протокол (HTTP или HTTPS) он выбирает чисто по схеме из переданного URL.
* **WebSocket-клиент** построен на библиотеке `websocketpp`. В неё вкомпилированы два бэкенда: `asio_client` (чистый TCP без шифрования) и `asio_tls_client` (с TLS). Схема (`ws://` или `wss://`) выбирается автоматически по URI.

### Что это дает на практике:
Для перевода колонки на свой локальный сервер **не обязательно мучиться с генерацией самоподписанных SSL-сертификатов** и подменой доверенных CA. Достаточно прописать в `/system/vendor/quasar/quasar.cfg` обычные незашифрованные адреса:
```json
{
  "common": {
    "backendUrl": "http://192.168.1.50:8080"
  },
  "aliced": {
    "uniProxyUrl": "ws://192.168.1.50:8081/uni.ws",
    "uniProxyQuicUrl": ""
  }
}
```

## 🔁 2. Сторож Wi-Fi (Wi-Fi Reseter) и цикличные обрывы

Если вы изолировали Станцию от интернета (например, заблокировали внешние серверы Яндекса на роутере), колонка может каждые **120 секунд кратковременно рвать Wi-Fi соединение**.

### Причина:
В фоновом демоне `maind` работает встроенный сторож соединения (`wifi_reseter`). Он периодически опрашивает проверочный адрес `generate_204` на серверах Яндекса. Если несколько проверок подряд проваливаются, демон считает, что завис Wi-Fi драйвер, и выполняет принудительный рестарт интерфейса `wlan0`.

### Как предотвратить:
1. Поднимите на своём локальном роутере/сервере заглушку на порту 80/443, отвечающую HTTP-кодом `204 No Content` на любой запрос `/generate_204`.
2. Заверните домен проверки в локальный DNS роутера.

## 🗺️ 3. Зашитые IP-адреса: `DnsFallbackMap`

Даже если на роутере настроена подмена DNS, некоторые сервисы колонки могут обходить системный резолвер и обращаться напрямую к серверам Яндекса по IP.

### Причина:
В бинарнике и системном конфиге есть таблица `DnsFallbackMap`. Если DNS-запрос не проходит или завершается таймаутом, Станция берет захардкоженные публичные IP Яндекса (`77.88.8.x`, `5.255.255.x`, `87.250.250.x`).

### Решение:
* При полной изоляции очистите блок `DnsFallbackMap` в `quasar.cfg`.
* На роутере используйте принудительный **DNAT 53-го порта** и блокировку диапазона подсетей Яндекса для IP-адреса колонки.

## ⚡ 4. Перезапуск Quasar через ADB и `setsid`

Частая ошибка при разработке: попытка перезапустить стек Quasar простой командой:
```sh
# ТАК ДЕЛАТЬ НЕЛЬЗЯ:
killall quasar_launcher2
/system/vendor/quasar/run.sh &
```
Как только вы закроете сессию `adb shell`, запущенный супервизор моментально умрет вместе с закрытием pty-терминала, и колонка превратится в «молчащий кирпич» до перезагрузки по питанию.

### Правильный перезапуск:
Запуск нового процесса супервизора обязательно должен быть отвязан от управляющего терминала с помощью `setsid`:

```sh
killall quasar_launcher2
sleep 2
killall -9 maind

cd /system/vendor/quasar
mount -o remount,rw /
setsid ./run.sh </dev/null >/dev/null 2>&1 &
```

## 🕒 5. Зависимость от системного времени (NTP)

У компактных моделей (Лайт, Мини 1) на плате **нет батарейки и аппаратных часов реального времени (RTC)**.

При включении питания колонка стартует с датой 1970 года. Время синхронизируется через NTP-демон `chronyd` и кастомный протокол `netclock` Яндекса (`udp 11124/11125`).

### Последствия сбоя времени:
* Все проверки TLS-сертификатов падают с ошибкой `Certificate Not Yet Valid`.
* Логирование и очереди задач в `aliced` зависают или падают в segmentation fault.
* Поэтому при автономной работе колонка должна иметь доступ хотя бы к локальному NTP-серверу на вашем домашнем роутере.

## 📋 6. Где смотреть реальные логи сбоев

Если Алиса молчит, кнопки не реагируют, а музыка не играет — 99% ответов находятся в каталоге логов:

```sh
# Логи главных подсистем
tail -f /data/quasar/daemons_logs/maind.log
tail -f /data/quasar/daemons_logs/yiod.log

# Крэш-дампы ядра и памяти
ls -la /sys/fs/pstore/
ls -la /data/tombstones/
```
Все непредвиденные падения C++ потоков, ошибки парсинга Protobuf и сбои GStreamer выводятся туда в текстовом виде.
