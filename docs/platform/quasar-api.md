# Спецификация HTTP API quasar.yandex.net

Полная спецификация клиент-серверного протокола между умными колонками Яндекс и облачным бэкендом `https://quasar.yandex.net`. Спецификация восстановлена по реверс-инжинирингу клиентского кода C++ и исходников прошивки.

Именно на знании этих эндпоинтов строятся эмуляторы сервера (MiniADB, eQuasar, quasar-server, quasar-unlock) и механизмы внедрения root-прав.

---

## 🔐 Базовые соглашения и безопасность

### 1. Адресация (Base URL)
По умолчанию в конфигурационных файлах станций (`quasar.cfg`) задан адрес:
```text
https://quasar.yandex.net
```
При включении отладочного режима (`q backend-dev`) колонка переключается на `https://quasar.yandex.ru/dev`.

### 2. Авторизация и подпись запросов (X-Quasar-Signature)
Каждый критический запрос от колонки к серверу снабжается двумя заголовками:
1. `Authorization: OAuth <oauth_token>` — токен учетной записи владельца.
2. `X-Quasar-Signature: <timestamp>:<signature>` — криптографическая подпись тела запроса, предотвращающая подделку:
   * **Алгоритм:** HMAC-SHA256.
   * **Ключ подписи:** `server_private_key` (или секрет устройства, хранящийся в защищенном файле `/data/quasar/devices.json`).
   * **Подписываемая строка:** конкатенация метода, пути, временной метки Unix и тела запроса (body).

## ⚡ Ключевые эндпоинты

### 1. Синхронизация конфигурации: `/get_sync_info` { #get-sync-info }

Этот запрос отправляется демоном `syncd` при каждой загрузке колонки и периодически раз в несколько часов.

* **Метод:** `POST`
* **URL:** `/get_sync_info`
* **Тело запроса:** JSON с текущим состоянием устройства (`platform`, `deviceId`, текущие хэши конфигов).

#### Формат ответа сервера:
Сервер возвращает дерево конфигураций, управляющее поведением колонки:

```json
{
  "status": "ok",
  "system_config": {
    "adbd": {
      "forceDisable": false,
      "remoteActivation": true,
      "network": true
    },
    "monitoring": {
      "enabled": true
    }
  },
  "glagol": {
    "enabled": true,
    "security": "strict"
  }
}
```

!!! tip "Механика вектора взлома через `/get_sync_info`"
    Локальный MITM-прокси перехватывает этот запрос и принудительно дописывает в `system_config.adbd`:  
    `"remoteActivation": true` и `"network": true`.  
    Получив такой ответ, скрипт `activate_adb.sh` в прошивке колонки автоматически создает постоянные маркеры в `/data/quasar/` и запускает `adbd` на порту **5555**!

### 2. Проверка обновлений прошивки: `/check_updates` { #check-updates }

Запрос демона `updatesd` для проверки наличия новой OTA-прошивки.

* **Метод:** `POST`
* **URL:** `/check_updates`
* **Тело запроса:**
  ```json
  {
    "platform": "yandexmini_2",
    "version": "0.369.1.25.4712742930.20260928",
    "device_id": "M10FHG010WKX1K"
  }
  ```

#### Ответ при отсутствии обновлений (OTA-Shield):
```json
{
  "hasUpdate": false
}
```
*(Именно этот ответ отдают скрипты защиты от обновлений, чтобы заблокировать принудительную установку патчей от Яндекса)*.

#### Ответ при наличии обновления (выдача даунгрейда/рут-прошивки):
```json
{
  "hasUpdate": true,
  "updateId": 149632,
  "version": "0.366.1.2.4599178412.20260904.296",
  "downloadUrl": "https://quasar.s3.yandex.net/ota/yandexmini_2/firmware.zip",
  "size": 66780672,
  "crc32": 3776602757,
  "sha256": "eb8c6d4eb...1036"
}
```

Колонка скачивает zip-архив с указанного `downloadUrl` (поддерживается HTTP Range для докачки), проверяет контрольную сумму CRC32, распаковывает образ и запускает `update_script.sh`.

### 3. Авторизация локального Glagol: `/glagol/token` { #glagol-token }

Используется для получения временного токена локального управления.

* **Метод:** `GET`
* **URL:** `/glagol/token?device_id=<DEVICE_ID>`
* **Заголовки:** `Authorization: OAuth <OAUTH_TOKEN>`

#### Формат ответа:
```json
{
  "status": "ok",
  "token": "4a7f9c2e-8123-4567-89ab-cdef01234567"
}
```
Полученный токен передается в WebSocket-сообщении при подключении к `wss://<IP_колонки>:1961/` для локального управления звуком и сценариями.

---

### 4. Регистрация Push-уведомлений: `/push_subscribe`

Колонка регистрирует свой транспортный канал в сервисе Яндекс Xiva:

* **Метод:** `POST`
* **URL:** `/push_subscribe`
* **Параметры:** `device_id`, `service_name=quasar`, `push_token`.
* По этому каналу облако может мгновенно прислать колонке push-директиву на включение сценария или немедленный запуск проверки обновлений.

---

### 5. Телеметрия и пинги: `/update_device_state`

Каждые несколько минут колонка рапортует серверу о своем здоровье:
* Аптайм, уровень Wi-Fi сигнала (RSSI);
* Текущий статус воспроизведения плеера;
* Температура процессора и объем свободной памяти.
