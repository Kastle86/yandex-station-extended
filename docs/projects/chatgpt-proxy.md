# Своя LLM (ChatGPT / Claude / Ollama) вместо Алисы

Архитектура гибридного прокси: как заменить стандартную «болталку» Алисы на современную нейросеть (ChatGPT, Claude или локальную Ollama), полностью сохранив при этом управление умным домом, таймеры, будильники и музыку.

---

## 💡 Почему нельзя просто подменить HTTP-бэкенд

В прошивке `quasar` все голосовые запросы идут не по HTTP (`backendUrl`), а через постоянное WebSocket-соединение с сервисом **Uniproxy** (`wss://uniproxy.alice.yandex.net/uni.ws`).

Через этот единый WebSocket-поток передается всё:
* Бинарные аудио-чанки с микрофонов (голос пользователя);
* Распознавание речи (ASR) на сервере;
* Классификатор намерений (VINS / Megamind);
* Сценарии умного дома, таймеры, навыки и синтез речи (TTS).

«Болталка» (ответы на общие вопросы) — это не отдельный сервер, а всего лишь один из сценариев (`general_conversation`) внутри общего диалогового потока. Поэтому правильное решение — **WebSocket MITM-прокси перед Uniproxy**.

---

## 🏗️ Гибридная архитектура

```text
Колонка (демон aliced)
   │  wss://ваш-прокси/uni.ws (голос, токен, JSON)
   ▼
Ваш WebSocket-прокси
   │  wss://uniproxy.alice.yandex.net/uni.ws
   ▼
Yandex Uniproxy (распознавание речи ASR)
   ├─ Умный дом / Музыка / Таймеры ──► Пропускаем штатный ответ Яндекса
   │
   └─ Интент "болталка" (general_conversation)
         │
         ▼
      [ Запрос к ChatGPT / Claude / Ollama ]
         │
         ▼
      Подмена текста в TTS-директиве (Алиса озвучивает ответ своим голосом)
```

---

## 🔧 Как перенаправить колонку на свой прокси

Демон `aliced` берет адрес Uniproxy из конфигурации `AliceConfig::getUniProxyUrl()`.  
Приоритет:
1. `system_config.uniProxyUrl` из ответа `/get_sync_info`;
2. Файловый конфиг на устройстве;
3. Дефолт: `wss://uniproxy.alice.yandex.net/uni.ws`.

### Вариант 1 (без модификации прошивки):
Ваш локальный сервер синхронизации (quasar-server / MiniADB) отдает в `/get_sync_info`:
```json
{
  "system_config": {
    "uniProxyUrl": "wss://192.168.1.50:8443/uni.ws"
  }
}
```

### Вариант 2 (на отрутованной колонке):
Если у вас есть root-доступ, адрес можно задать статически в `/system/vendor/quasar/quasar.cfg` (предварительно сделав `mount -o remount,rw /`).

## 🎯 Классификация интентов в прокси

Прокси слушает входящие сообщения от настоящего Uniproxy. В финальном JSON-ответе анализируется поле:
* `response.features.form_info.intent`

| Значение интента | Что это | Действие прокси |
|---|---|---|
| `personal_assistant.general_conversation.general_conversation` | Обычный разговорный диалог | **Перехватывать и отправлять в LLM** |
| `personal_assistant.scenarios.external_skill_gc` | Режим расширенной болталки | **Перехватывать и отправлять в LLM** |
| `personal_assistant.scenarios.iot_*` | Управление лампочками, розетками | Пропускать штатный ответ Яндекса |
| `personal_assistant.scenarios.music_*` | Включение музыки / треков | Пропускать штатный ответ Яндекса |
| `personal_assistant.scenarios.alarm_*` | Будильники и таймеры | Пропускать штатный ответ Яндекса |

## 🗣️ Как Алиса произносит ответ от LLM

Когда прокси получает текстовый ответ от ChatGPT / Claude, он подменяет директиву синтеза речи:

1. В ответе Uniproxy находится директива `Tts.PlayPlaceholder` или `SpeechKit.Speak`.
2. Прокси заменяет оригинальный текст Яндекса на ответ от вашей LLM:
   ```json
   {
     "directive": {
       "header": {
         "name": "Speak",
         "namespace": "SpeechKit"
       },
       "payload": {
         "text": "Ответ от ChatGPT, озвученный родным голосом Алисы"
       }
     }
   }
   ```
3. Колонка получает модифицированную директиву и воспроизводит синтезированную речь через локальный GStreamer-пайплайн.

В результате вы получаете умную колонку с мощным интеллектом GPT-4 / Claude / Llama, сохраняя при этом идеальное распознавание русской речи и интеграцию со всеми домашними устройствами Яндекса.
